# ВШЭ-Банк: Модуль Учет Финансов

## Общая идея решения

В рамках проекта реализован модуль «Учет финансов», предназначенный для управления личными финансовыми средствами пользователей банка. Основной функционал включает:
- **Работу с доменной моделью:** создание, редактирование и удаление счетов, категорий и операций (доходов/расходов).
- **Аналитику:** подсчет разницы между доходами и расходами, группировку операций по категориям и выборку операций за заданный период.
- **Импорт и экспорт данных:** поддержка форматов CSV, JSON и YAML. Импорт реализован с использованием шаблонного метода, а экспорт — через паттерн Посетитель.
- **Управление данными:** возможность пересчета баланса счета при обнаружении несоответствий.
- **Прокси для персистентности:** использование in‑memory кэша с синхронизацией с «базой данных» (эмуляция через файл).
- **Использование DI-контейнера:** для внедрения зависимостей (на базе Microsoft.Extensions.DependencyInjection).

При необходимости можно использовать отдельные команды, декораторы, фабрику доменных объектов для централизованного создания и валидации, что исключает дублирование кода.

## Принципы SOLID и GRASP

Реализованы следующие принципы:

- **Single Responsibility Principle (SRP):**  
  Каждый класс отвечает за свою конкретную задачу.  
  - **Доменные модели (BankAccount, Category, Operation)** – отвечают только за хранение и обновление своих данных.
  - **Фасады (BankAccountFacade, CategoryFacade, OperationFacade, AnalyticsFacade)** – инкапсулируют логику управления соответствующими сущностями.

- **Open/Closed Principle (OCP):**  
  Система расширяема через использование паттернов, таких как Command, Decorator, Visitor и Template Method, что позволяет добавлять новые форматы импорта/экспорта или сценарии без модификации уже существующего кода.

- **Dependency Inversion Principle (DIP):**  
  Зависимости внедряются через конструкторы (например, DomainFactory передаётся в фасады), что упрощает тестирование и поддержку кода.

- **High Cohesion и Low Coupling (GRASP):**  
  Логика разделена между специализированными классами (фасады, доменные модели, репозитории), что снижает связанность и повышает модульность системы.

## Реализованные паттерны GoF

### 1. Фасад (Facade)
- **Реализация:**  
  Классы `BankAccountFacade`, `CategoryFacade`, `OperationFacade`, `AnalyticsFacade` и центральный `FinanceFacade` инкапсулируют операции управления доменной моделью и аналитикой.  
- **Важность:**  
  Обеспечивает единый интерфейс для работы с системой, упрощая взаимодействие между различными компонентами.

### 2. Команда (Command) и Декоратор (Decorator)
- **Реализация:**  
  Интерфейс `ICommand`, класс `LambdaCommand` инкапсулируют действия пользователя. `TimeMeasurementDecorator` добавляет измерение времени выполнения команд.  
- **Важность:**  
  Позволяет легко добавлять новую функциональность (например, логирование или кэширование) без изменения логики самих команд.

### 3. Шаблонный метод (Template Method)
- **Реализация:**  
  Абстрактный класс `DataImporter` и его наследники (`CsvImporter`, `JsonImporter`, `YamlImporter`) реализуют различную логику парсинга, при этом общая последовательность действий сохраняется.  
- **Важность:**  
  Позволяет единообразно обрабатывать импорт данных из различных форматов с минимальным дублированием кода.

### 4. Посетитель (Visitor)
- **Реализация:**  
  Интерфейс `IExportVisitor` и его реализации (`CsvExportVisitor`, `JsonExportVisitor`, `YamlExportVisitor`) используются для обхода доменных объектов и формирования экспортированного файла.  
- **Важность:**  
  Разделяет логику экспорта от доменной модели и позволяет легко расширять функциональность экспорта.

### 5. Фабрика (Factory)
- **Реализация:**  
  Класс `DomainFactory` централизует создание объектов (BankAccount, Category, Operation) с валидацией входных данных и автоматическим присвоением идентификаторов.  
- **Важность:**  
  Позволяет избежать дублирования кода и гарантировать корректность создаваемых объектов.

### 6. Прокси (Proxy)
- **Реализация:**  
  Классы `DatabaseRepository` и `RepositoryProxy` реализуют работу с данными через файл (эмуляция базы данных) и обеспечивают in‑memory кэширование для повышения производительности.  
- **Важность:**  
  Позволяет обеспечить персистентность данных после перезапуска приложения и эффективно управлять чтением/записью данных.

## Инструкция по запуску приложения

1. **Установка зависимостей:**  
   Убедитесь, что установлен .NET SDK (рекомендуется .NET 5 или выше).  
   Если DI-контейнер не установлен, выполните в консоли:
   ```bash
   dotnet add package Microsoft.Extensions.DependencyInjection
   ```

2. **Сборка проекта:**  
   Откройте терминал в корневой папке проекта и выполните:
   ```bash
   dotnet build
   ```

3. **Запуск приложения:**  
   После успешной сборки запустите приложение:
   ```bash
   dotnet run
   ```

4. **Работа с консольным меню:**  
   Приложение предоставляет текстовое меню, в котором можно выбрать:
   - Управление счетами, категориями и операциями.
   - Выполнение аналитических запросов.
   - Импорт и экспорт данных (CSV, JSON, YAML).
   - Пересчет баланса.
   - Сохранение и загрузку данных в/из «БД» через прокси.
   - Выход из приложения.

5. **Дополнительные инструкции:**  
   - Для импорта/экспорта укажите корректный путь к файлам.  
   - В случае ошибок следуйте выводимым сообщениям в консоли.
